Intro

Agora iremos ver a diferenca pratica entre null e undefined, e como podemos usa-los com objetos.

Porem, se digitarmos um seletor invalido no querySelector, o resultado sera null, pois nenhum elemento foi encontrado.

Cada elemento da pagina possui propriedades que permitem acessar o elemento anterior ou o proximo elemento.

Para obter uma referencia ao elemento anterior, utilizamos previousElementSibling. Caso nao exista um elemento anterior, o resultado sera null. Ja se digitarmos a propriedade de forma incorreta, como prevElementSibling, o resultado sera undefined, pois essa propriedade nao existe.

Resumo:
• null = a propriedade existe, mas nao possui valor no momento.
• undefined = a propriedade nao existe ou nunca foi definida.

Por isso, em nossos proprios objetos, podemos utilizar null como um valor temporariamente vazio.

O mesmo conceito tambem vale para arrays:

Quando adicionarmos informacoes tanto em passport quanto no array, substituindo o valor null, os dados serao exibidos normalmente.

Para cada propriedade de um objeto, podemos definir um valor padrao. Isso facilita o desenvolvimento, pois o autocompletar da IDE reconhece todas as propriedades existentes, mesmo que ainda estejam vazias.

Por isso, e comum declarar todas as propriedades de um objeto (ou classe) logo na criacao, atribuindo valores como null, 0, false ou "", dependendo do tipo esperado.

Importante: mantenha o tipo do valor. Por exemplo, se age representa um numero, seu valor inicial pode ser 0, e nao uma string ou outro tipo de dado.
